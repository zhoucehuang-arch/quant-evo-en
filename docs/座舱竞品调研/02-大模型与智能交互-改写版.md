# 一、现有数据能得出的结论

## 1. 路线差异和声音部分完全一致：理想给选择，蔚来给唯一解

这是这次调研最有价值的发现——**跨模块印证**。

| | 理想 L9 Livis | 蔚来 ES9 |
|---|---|---|
| 模型切换 | ✅ 快速 / 专家可切 | ❌ 只有 Nomi |
| 第三方模型 | ✅ Kimi、MiniMax | ❌ |
| 主动降噪 | 给开关 | 不给开关 |
| 音效 | 用户自己调 + 分享码 | 智能音效自动托底 |
| 音场 | 手动选六种模式 | 智能音场自动匹配 |

声音那边看到的"理想把控制权交给用户，蔚来替用户决定"，在大模型这边一模一样。这不是巧合，是两家的产品哲学。

**两条路都有代价**：
- 理想：用户得自己知道什么时候用哪个模型——但用户根本不知道自己的问题算不算"复杂"
- 蔚来：Nomi 答不好的时候没有备选

**这条对我们最有用**：路线差异是可以被观察到的，而且是稳定的。以后看这两家的任何新功能，都可以用这把尺子先预判一下它会怎么做。

## 2. 理想的"专家模式"目前不可用，分项打分把这一点掩盖了

原报告的分项打分：

| | 语义理解 | 反应速度 |
|---|---|---|
| 理想·快速 | 5 分 | 7 分 |
| 理想·专家 | **8 分（最高）** | **4 分（最低），最慢约 15 TPS** |
| Nomi | 6 分 | 6 分 |

单看语义理解，理想专家模式 8 分是全场第一。但 15 TPS 是什么概念——说一句 30 字的回答要等 2 秒才吐完，加上首字延迟，用户在车里会以为车没听见，然后再说一遍。

**在这个延迟下，语义理解再准也没用。**

所以综合结论应该是：理想实际能用的是快速模式，而快速模式的语义理解（5 分）是低于 Nomi（6 分）的。**语音交互里速度不是一个可以和准确率权衡的指标，它是准入门槛。**

**这也暴露了一个方法问题**：分项打分会得出反常识的结论。以后分数只作为证据放明细里，结论一律给综合判断，并写清楚是怎么综合的。

**顺带一个产品判断**：让用户手动选"快速/专家"，本质是把工程上的速度-质量权衡甩给了用户。正确做法是系统根据问题复杂度自动路由。理想做成显式开关，说明自动路由的能力还不到位，或者是想让用户感知到"我们有个很强的专家模型"。**这个开关我们不要抄。**

## 3. 多模态是两家共同的空白，也是最大的机会

|  | 车内视觉理解 | 车内手势 | 车外视觉理解 | 乘员识别 | 语调 | 声色 |
|---|---|---|---|---|---|---|
| 理想同学 | ❌ | ✅ | ❌ | ✅ 声纹 | ❌ | ✅ |
| Nomi | ❌ | ❌ | ❌ | ✅ 声纹 | ❌ | ✅ |

车内图像、车外识别、语调识别，两家全是 0。

座舱里有一堆摄像头和麦克风，但大模型只用到了文字这一路。用户说"这个是什么"指着窗外，两家都答不了；用户语气明显不耐烦，两家都感知不到。

**这是最大的机会点，也是最难的**。摄像头数据上不上云、隐私怎么处理、时延怎么控制，都是硬问题。但正因为难，谁先做出来谁就领先一代。

**声音部分的第 12 条（动态压低）也在这里交汇**：判断一条播报该压多少音量，需要语义理解；判断用户是不是在专心开车，需要视觉。声音和大模型不是两个独立模块，接口在这里。

## 4. 多 Agent 打架是共性问题

原报告实测记录：

> 都存在问题判断时，上下文和各 Agent 间触发逻辑的冲突问题

两家都有，说明这是当前技术方案的通病：多个 Agent（出行、用车、娱乐、闲聊）挂在同一个语音入口，靠意图识别分发。问题在于意图边界是模糊的——"附近有什么好吃的"该走出行还是娱乐？"车里有点冷"该走车控还是闲聊？

**根子上是缺一个统一的意图路由和仲裁层**，现在的做法更像是几个 Agent 抢麦克风。

**对我们**：Agent 数量不是竞争力，路由准确率才是。做规划的时候，先把路由和仲裁的架构定下来，再往上挂 Agent；反过来做，Agent 越多体验越差。

## 另外两条零散但确定的发现

- **理想的访客模式形同虚设**：实测发现访客模式下依然能看到行程记录和播放记录。这是明确的隐私缺陷，商务用车场景下是硬伤。这条可以作为我们的宣传点。
- **理想的跨会话记忆有限**：对"上次播放"记忆模糊，会用推荐话术回避（快速模式下更明显）。用话术掩盖能力缺失是个常见做法，但用户试两次就会发现。

# 二、测试项怎么重新组织

原报告分了 2.1 模型能力底座 / 2.2 基础智能助手 / 2.3 进阶智能能力 / 2.4 情感体验，下面 12 张表。问题：

- **重叠严重**：端侧大模型在"模型架构"里出现一次，在"大模型能力范围"里又出现一次，在"语音基础-弱网降级"里第三次出现，三处内容完全一样
- **端到端语音**出现两次
- **有些项填不出来**：唤醒速度、识别率没有测试方法就填不了；"上下文接续"和"跨对话多轮"边界不清
- **"差异点"表全是空壳**：每节下面挂了一张只有表头的表

按声音部分的思路重整——**不分层级，按能力挨个测，一项只出现一次**：

| 序 | 测试项 | 为什么测（能得出什么结论） | 优先级 |
|---|---|---|---|
| 1 | 首字延迟 + 吐字速度 | 语音交互的准入门槛，直接决定可用性 | P0 |
| 2 | 复杂指令完成率 | 语义理解的核心，用固定题库打分 | P0 |
| 3 | 多 Agent 路由准确率 | 已知两家共同短板，值得测清楚差多少 | P0 |
| 4 | 上下文接续（代词替换、指令改写） | 决定能不能连着说话，不用每句重复 | P0 |
| 5 | 跨会话记忆与偏好学习 | 已知理想有短板，需要量化 | P1 |
| 6 | 多模态：车内视觉 / 车外视觉 / 语调 | 已知两家都是 0，主要是确认没有 | P1（确认即可） |
| 7 | 弱网与离线降级 | 端侧能力的真实水平 | P1 |
| 8 | 免唤醒 / 分区 / 声纹 / 方言 | 都有，测的是准确率不是有没有 | P1 |
| 9 | 车外防误唤醒、车内防电子音误唤醒 | 安全项 | P1 |
| 10 | 隐私（访客模式） | 已发现理想有硬伤，需要测蔚来 | P1 |
| 11 | 卡片/场景交互与多屏分发 | 理想的优势区，看它做到什么程度 | P2 |
| 12 | 任务编排（任务大师 / 快捷场景） | 自定义能力的天花板 | P2 |
| 13 | AIGC（AI 卡片生成 vs AI 场景生成） | 两家投向不同，值得对比 | P2 |
| 14 | IP 形象与人格设定 | Nomi 有实体，理想没有，差异明显 | P2 |
| 15 | 主动服务与情绪关怀 | 已知语调识别是 0，主动服务的触发只能靠其他信号 | P2 |
| 16 | TTS 音色与自定义 | 感知强、成本低 | P2 |

**测试方法的两点建议**（原报告最缺的就是这个）：

1. **固定题库**。语义理解、复杂指令、上下文这几项，必须用同一套题去测两台车，否则分数没有可比性。题库建议 30 题起，覆盖模糊意图、一句多意图、复合条件、口语化。题库本身就是可复用的资产，测下一款车还能用。
2. **延迟要用秒表或录屏计。**"感觉有点慢"不能进报告，"首字 1.8 秒"可以。
