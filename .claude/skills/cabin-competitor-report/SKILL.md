# 智能座舱竞品调研报告

竞品报告的价值不在于把别人写清楚，而在于给我们的决策提供输入。
**每个功能分析完，都必须回答：跟，还是不跟，还是换个做法。**

## 一、两个容易混的东西

写报告前先分清：

- **评价角度（尺子）** —— 用来看每一个功能的，是分析工具
- **结论分点（骨架）** —— 用来组织结论的，是表达结构

"功能 / 体验 / 未来发展"是**尺子**，不是骨架。结论按尺子分，读的人还是不知道该干什么。
**结论要按"所以呢"分。**

## 二、尺子：每个功能都问这五个问题

1. **有没有** —— 功能覆盖。对照自家基准表打勾即可，正文不展开（基础项已经是行业门槛）
2. **好不好用** —— 路径几层、响应多快、找不找得到、能调多细、前后排一不一致
3. **聪不聪明** —— 全手动 / 给推荐 / 系统自己判断并执行
4. **为什么这么做** —— 背后的场景假设和用户模型。**"深挖"发生在这一步**
5. **缺什么** —— 各自的不足，以及两家都没解决的（后者最有价值）

第 4 问是区分"做了调研"和"做了思考"的分水岭。
写法是：**它假设用户是谁、在什么场景下、有什么需求**，然后看这个假设成不成立。

## 三、骨架：一页结论的五个分点

```
1. 谁更强，强在哪
   一句话定调 + 2~3 条能被验证的理由
   同时必须写"但它不是全面领先"，列出短板

2. 两家走的不是同一条路
   路线差异，不是谁好谁坏
   用一张小表把路线差异在多个功能上的表现并排列出来
   写清楚每条路各自的代价

3. 两家都没做好的
   = 我们的机会。这一节往往是全篇最有价值的

4. 我们跟什么、不跟什么
   分四档：必须跟 / 换个做法跟 / 先不跟 / 别人没做但我们可以做
   每条一句话，直接给动作

5. 下一步还要看什么
   没测完的、要持续跟的、结论里靠推测的
```

## 四、报告的三层结构

| 层 | 内容 | 给谁看 | 长度 |
|---|---|---|---|
| L1 一页结论 | 上面五个分点，**纯文字，不用表格** | 30 秒扫完的人 | 1 页 |
| L2 分功能分析 | 每个功能一节，见下面的模板 | 3 分钟想知道该干什么的人 | 主体 |
| L3 明细与证据 | 完整对比表、截图、实测记录、信息来源 | 要查证的人 | 附录 |

## 五、单个功能的模板

**不要按"基础/智能/体验"分章节。**归类本身有争议（头枕音响算基础还是智能？），而且会把同一条主线上的功能拆散。
**功能挨个排，排序按"差异大小 × 用户感知强度"，差异大的在前。完全一致的项收进末尾一个清单，一句话带过。**

```markdown
## N. 功能名

**一句话结论：**（谁强/怎么不一样，要能被验证）

**差异点**

| 差异维度 | A 车 | B 车 |
|---|---|---|
（只放有差异的行。两边一样的不进表——除非"一样本身很意外"，
 比如"两家都没做报警音分级"，那属于机会点，要写）

**为什么这么做**

- A 车：（它假设用户是谁、在什么场景下用）
- B 车：（同上）

**缺什么**

- A 车的问题：
- B 车的问题：
- 两家都没解决的：（最有价值的一条）

**对我们**

- 跟 / 不跟 / 换个做法，一句话说清楚
```

## 六、对比表的规范

**状态标记**

| 标记 | 含义 |
|---|---|
| ✅ | 有，且做法与我方基准一致 |
| ⚠️ | 有，但做法不同 —— **后面必须写清楚怎么不同** |
| ❌ | 确认没有 —— 说明是没做，还是做不到 |
| ? | 没测到 —— **不要留空，留空等于默认没有** |

用 ❌ 标"用了另一种做法"的功能，会让读的人得出错误结论。这是最常见的错误。

**其他规范**

- 单元格只放能对齐比较的短语，超过 15 字的分析挪到表格外的正文
- 表格里不要有"总结"栏。总结要回答"那又怎样"，塞在单元格里没人看得到
- 每条事实标来源：`[实测]` / `[官方]` / `[网络]`。网络来源标出处和日期
- 参数类数据（功率、数量）要说清楚和体验的关系，别列完就过

## 七、打分的规矩

**分项打分会得出反常识的结论。**

真实案例：某车"语义理解 8 分（全场最高）"，同一行写着"最慢 15 TPS"。
15 TPS 意味着 30 字的回答要等 2 秒才吐完，用户会以为车没听见。这个延迟下语义理解再准也没用。

规矩：
- 分项分数只作为**证据**放明细里
- 结论一律给**综合判断**，并写清楚是怎么综合的
- 有些指标是**准入门槛**不是权衡项（语音交互的响应速度就是），门槛不过，其他分数不参与比较
- 打星级必须先有评分标准。写不出标准就别打星
- **没测完就不给结论。**给了没证据的结论比留白危险得多

## 八、交稿前的检查清单

**内容**
- [ ] 每个功能都回答了"对我们意味着什么"
- [ ] 每个功能都写了"为什么这么做"（场景假设），不只是罗列差异
- [ ] 找出了"两家都没做好的"，并至少有一条能立项
- [ ] 结论里的每条理由都能拿车去验证
- [ ] 推测的地方标明了是推测
- [ ] 没测的项标了 `?` 或列进待补清单，没有留空

**格式**
- [ ] 结论用文字不用表格
- [ ] 表格里只有差异项，没有两边一样的行
- [ ] 状态标记用了 ✅⚠️❌? 四档，⚠️ 后面写了怎么不同
- [ ] 单元格里没有长段落
- [ ] 每条事实标了来源

**文字**
- [ ] 过一遍 `plain-chinese-writing` 的自查六条

## 九、常见的坑

1. **只写事实不给判断。**整页 ✅❌，看完不知道 so what
2. **"总结"栏写成事实复述。**"两家音源分类齐平"是事实不是总结
3. **按维度分章节。**把同一条主线上的功能拆到了不同章节，看不出对手的整体意图
4. **参数堆砌。**列了喇叭数量和峰值功率，但结论和参数对不上，也不解释为什么
5. **把无差异项写进正文。**法规强制项（低速行人提示音）、已成标配项（杜比全景声）不该占篇幅
6. **只有别人没有我们。**报告写成了竞品说明书
7. **没测完就打分。**空表格配星级，是这份报告最容易被问倒的地方

## 十、有价值的分析长什么样

判断一段分析有没有价值，看它有没有做到下面至少一条：

- **从产品表现反推出对方的用户假设**
  例：ES9 音区数等于座位数 → 它假设车里的人在干不同的事；L9 前后两舱 → 它假设大家在听同一个东西

- **指出一条路线的隐藏代价**
  例：不给降噪开关 = 对自己算法有信心，代价是用户不适时没有退路，而且用户只会说"坐这车头晕"，问题都定位不到

- **找到跨模块的一致性**
  例：声音上"给开关 vs 给结果"，大模型上"可切模型 vs 唯一模型"，是同一条产品哲学。找到之后可以用它预判对方的下一个功能

- **把功能问题上升成方法问题**
  例：一键静音做实体键 → **交互载体应该由需求的时间压力决定，不是由功能重要性决定**。这条能推广到座舱其他功能的评审

- **指出两家都没解决、且能立项的空白**
  例：报警音没有统一分级和仲裁，重要的和不重要的一样响，用户会整体麻木。和安全挂钩，容易立项

- **对功能的实际生命周期做判断**
  例：5D 短片只有 3 首歌 → 这类强感知功能的生命周期由内容供给决定，上线惊艳，一周后归零。立项前先回答"内容从哪来、多久更新"
